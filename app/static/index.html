KeyCycle

Encryption keys created, rotated, expired and revoked, with a record nobody can quietly rewrite.

The vault

Every key is generated here and never leaves unwrapped.

Each key is AES-256-GCM, wrapped under a master key that lives only in memory. While the vault is locked, no key can be used.

One passphrase

The master key is never stored.

It’s derived from the vault passphrase with Argon2id, slow on purpose so guessing is expensive.

A key’s life

Five states, each one enforced by the server.

  1. Created
  2. In use
  3. Rotated
  4. Expired
  5. Revoked

Created

An administrator creates it. Version 1 is wrapped by the vault.

In use

Operators encrypt and decrypt with it. Every request gets a recorded decision.

Rotated

A new version takes over. Older versions still decrypt older data.

Expired

Past its date, every use is refused.

Revoked

Permanent. Every later use is refused and recorded.

The record

Every action is chained to the one before it.

Edit or remove any entry, and verification names the first one that no longer fits.

Six audit entries, #41 to #46, linked as a chain. Entry #44 is edited to hide a denied request; verification walks the chain from #41 and stops at #44, the first entry that no longer fits.

 

Three roles

The server checks every request against the caller’s role.

 

Administrator

Manages keys, users and backups. Uses test keys only.

Operator

Encrypts and decrypts with standard keys.

Viewer

Reads metadata and outcomes, never plaintext.
